# 旅行家Pro · 景区AI数字人导游平台
## 商业计划书

> **版本**：V1.0 · **日期**：2026年7月  
> **项目名称**：旅行家Pro（AI-guide）  
> **技术栈**：Next.js 16 · React 19 · DeepSeek · Live2D · PostgreSQL · Vercel  
> **定位**：面向中国智慧景区的 AI 数字人导游与运营一体化 SaaS 平台

---

## 一、执行摘要

旅行家Pro是一款深度融合大语言模型（LLM）、Live2D数字人、混合检索增强生成（Hybrid RAG）与多模态视觉识别技术的景区智能导游与运营系统。项目以"AI数字人小玉"为交互核心，向游客提供7×24小时语音对话导览、个性化行程规划、VR即拍即识文物解读等沉浸式体验；同时向景区运营方提供实时数据大屏、RAG知识库管理、情感分析报告等数字化运营工具。

**核心数据**：
- 13个页面路由，17个核心屏幕组件，20+个API端点
- 9张数据库表，支持完整的C端+B端业务闭环
- 竞赛合规度评估≈88/100分（第十五届中国软件杯A5赛题）
- 已完成功能覆盖率约95%，具备即时部署上线能力

## 二、项目定位与核心痛点

### 2.1 项目定位

旅行家Pro定位为**景区数字化智能导游SaaS平台**，聚焦两大核心用户：
- **C端游客**：需要个性化、沉浸式、多语境的导游服务
- **B端景区运营方**：需要低成本、可量化、数据驱动的运营工具

### 2.2 解决的核心痛点

| 痛点 | 现状 | 旅行家Pro解法 |
|------|------|--------------|
| 人力导游成本高 | 专业导游人均成本300-800元/天，旺季供不应求 | AI数字人7×24小时在线，边际成本趋近于零 |
| 导览内容千篇一律 | 固定讲解词无法适配不同游客需求 | LLM+用户偏好建模，老人/儿童/专业模式差异化讲解 |
| 文物信息获取困难 | 展品标牌字小、信息少、无法互动 | VR即拍即识：拍照1秒返回深度文化解读+语音讲解 |
| 景区运营数据缺失 | 缺乏实时客流、满意度、热点问题分析能力 | 实时数据大屏+AI情感分析+运营建议自动生成 |
| 知识库维护成本高 | 景区资料分散，难以统一管理和检索 | RAG知识库：上传PDF/Word自动向量化，语义检索 |

## 三、市场分析

### 3.1 市场规模

- **中国旅游市场**：2025年国内旅游人次预计突破70亿，旅游收入超8万亿元
- **智慧景区市场**：2025年智慧景区整体市场规模约650亿元，年复合增长率约18%
- **景区数字化渗透率**：目前国内5A级景区数字化率约45%，4A及以下景区不足15%，市场空间巨大
- **目标市场（SAM）**：全国约300个5A景区 + 2000个4A景区，潜在年收入空间约120亿元

### 3.2 独特市场认知

**核心洞察**：当前市场上景区导览产品存在两极分化——
1. **高端定制方案**（如科大讯飞、商汤科技）：硬件+软件打包，单项目造价500万+，中小景区无力承担
2. **低端语音导览App**（如讯飞听见、景区官方App）：仅提供录音播放，无AI交互能力，用户黏性低

**旅行家Pro的机会窗口**：SaaS模式切入，以订阅制降低景区采购门槛，同时通过DeepSeek等国产大模型降低推理成本，实现"高端能力、平民价格"的错位竞争。

### 3.3 竞品对比

| 维度 | 传统语音导览 | 讯飞智慧景区 | 旅行家Pro |
|------|------------|------------|----------|
| 交互方式 | 录音播放 | 触屏问答 | 语音+文本+多模态 |
| 个性化能力 | 无 | 基础 | LLM驱动，老人/儿童/普通模式 |
| 文物识别 | 无 | 有（需硬件） | VR即拍即识（纯软件） |
| 情感交互 | 无 | 无 | Live2D表情+情感状态机 |
| 知识库管理 | 无 | 部分 | 完整RAG系统+自动向量化 |
| 部署成本 | 低 | 极高（500万+） | 低（SaaS订阅） |
| 数据分析 | 无 | 基础 | AI情感分析+运营建议 |

## 四、技术方案

### 4.1 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                        C端（游客）                            │
│  语音输入 → STT → LLM+RAG → TTS → Live2D数字人讲解          │
│  拍照 → 多模态视觉识别 → 文化解读 + 语音播报                  │
│  偏好设置 → 个性化行程规划 → 高德地图导航渲染                 │
└─────────────────────────────────────────────────────────────┘
                            ↕ API
┌─────────────────────────────────────────────────────────────┐
│                    Next.js 16 全栈服务层                      │
│  /api/qa/chat    RAG问答（流式SSE）                           │
│  /api/qa/tts     TTS语音合成（三级降级）                      │
│  /api/qa/stt     ASR语音识别（三级降级）                      │
│  /api/spots/recognize  多模态图像识别                         │
│  /api/routes/generate  AI行程规划生成                         │
│  /api/admin/*    B端管理接口                                  │
│  /api/mcp        MCP协议标准接口                              │
└─────────────────────────────────────────────────────────────┘
                            ↕
┌─────────────────────────────────────────────────────────────┐
│                      数据与AI层                               │
│  PostgreSQL + Drizzle ORM（类型安全）                         │
│  向量Embedding（1536维）+ 余弦相似度检索                       │
│  DeepSeek v3.1 / OpenAI / Qwen / Kimi（多模型热切换）         │
│  讯飞TTS → ElevenLabs → Google TTS（三级降级容灾）            │
│  Vosk本地ASR → Whisper-1 → 浏览器WebSpeech（三级降级）        │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 核心技术亮点

**① Hybrid RAG混合检索**
- 语义向量（权重0.7）+ 关键词匹配（权重0.3）混合重排
- Top-3相关文档注入System Prompt
- 问答准确率目标≥90%

**② 情感感知数字人**
- LLM强制输出情感标签（愉快/平静/伤感/思考）
- 前端解析驱动Live2D表情状态机切换
- 口型振幅同步TTS音频输出

**③ 三级降级容灾**
- TTS：讯飞→ElevenLabs→Google，任意节点宕机自动切换
- STT：Vosk本地→Whisper-1→浏览器WebSpeech
- Embedding：OpenAI→本地哈希向量兜底

**④ 无障碍多模式**
- `normal`：温暖知识型，≤200字
- `elder`：简洁慢速，无障碍路线优先，≤150字
- `child`：故事化讲解，活泼有趣，≤100字

**⑤ MCP协议标准化**
- 集成`@modelcontextprotocol/sdk`
- 7个标准工具（list-spots/ask-question/book-ticket等）
- 支持外部AI客户端直接调用

### 4.3 技术栈

| 层级 | 技术选型 | 理由 |
|------|---------|------|
| 框架 | Next.js 16 App Router | SSR+SSG+API Routes全栈一体 |
| UI | React 19 + Framer Motion 12 | 流畅动画，最新并发特性 |
| 样式 | Tailwind CSS v4 | 原子化，高性能 |
| 数字人 | Live2D Cubism SDK | 行业标准，12套内置角色 |
| 数据库 | PostgreSQL 16 + Drizzle ORM | 类型安全，JSONB向量存储 |
| AI大模型 | DeepSeek v3.1（国产优先） | 性价比最优，支持多提供商切换 |
| 部署 | Vercel + Cron | 零运维，弹性扩容 |
| 地图 | 高德JS API + Turf.js | 国内精度最优 |

## 五、解决方案的本质差异与不可替代性

### 5.1 与现有方案的本质差异

旅行家Pro不是"把语音导览做成App"，而是构建了一套**以AI为核心的景区数字神经系统**：

1. **从播放到对话**：传统导览是单向播放，旅行家Pro是双向多轮对话，支持追问、反驳、个性化扩展
2. **从规则到智能**：传统个性化靠规则引擎，旅行家Pro靠LLM动态生成，真正千人千面
3. **从孤岛到闭环**：C端导览数据实时流入B端分析，形成"游客行为→运营洞察→服务优化"的完整闭环
4. **从硬件到云端**：无需任何特殊硬件，游客用手机即可获得AI导览全体验

### 5.2 项目不可替代性

| 不可替代维度 | 说明 |
|------------|------|
| **技术壁垒** | Hybrid RAG + 情感状态机 + 三级降级容灾，形成完整技术护城河 |
| **数据飞轮** | 每次问答沉淀为知识库和用户偏好，用得越多越准 |
| **场景深度** | 12个深度定制页面，覆盖游览全链路（欢迎→导览→行程→识别→离园） |
| **运营赋能** | AI自动生成运营建议，景区无需数据分析团队即可获得洞察 |
| **生态锁定** | MCP协议接口 + PWA安装能力，构建平台生态入口 |
