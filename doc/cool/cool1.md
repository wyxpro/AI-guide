## 一、产品概述 🚀

### 1. 项目背景

| 维度 | 现状问题 | 驱动力 |

### 2. 项目简介

**旅行家** 是面向 C 端游客与 B 端景区运营方的**双端智慧伴游系统**，以 AI 数字人"小玉"为核心交互入口：

| 端 | 定位 | 核心能力 |
|----|------|---------|
| **C 端游客** | 7×24h 随身导游 | 多轮 RAG 问答、行程规划、拍照识景、景区 FM 广播、足迹勋章 |
| **B 端管理** | 运营数据中枢 | 知识库管理、数字人配置、实时数据大屏、AI 运营建议生成 |

### RAG 问答工作流

```
用户提问
  → IP 频率限制（rate-limit.ts）
  → 软鉴权（允许游客匿名）
  → 读取偏好（普通/老年/儿童模式）
  → Embedding 计算问题向量
  → 余弦相似度检索知识库 Top-3
  → 混合重排（0.7×语义 + 0.3×关键词）
  → 拼接 System Prompt + 知识上下文
  → 调用 deepseek-v4-pro（SSE 流式）
  → 解析情感标记 [情感: 愉快/思考/伤感/平静]
  → 异步写入 qa_logs + analytics_daily
```

## 四、特色功能 💎

### 1. 频域分析驱动唇形同步

无需 3D 渲染引擎，利用 HTML5 原生 API 实现高质量口型同步：

```
TTS 音频流播放
  → AudioContext.createMediaElementSource()
  → AnalyserNode.getByteFrequencyData()
  → 计算频率均值 → MouthAmplitude = avgFreq / maxScale
  → 映射为 SVG 贝塞尔曲线高度参数
  → requestAnimationFrame 逐帧更新嘴型
```

| 技术点 | 传统方案 | 本项目方案 | 优势 |
|-------|---------|-----------|------|
| 口型同步 | 3D Avatar SDK（>10MB） | Web Audio + SVG（<50KB） | 极轻量 |
| 情感表达 | 固定表情 | LLM 输出情感标记驱动动画帧 | 动态自然 |
| 延迟 | 500ms+ | <50ms | 实时流畅 |

### 2. VR 即拍即识（多模态）

### 5. 交互气泡与内嵌式加载（单气泡响应）

在用户提问后，AI回复气泡采用了“单气泡渐进加载与流式打字”的深度交互融合：

- **单气泡渲染**：将原来独立的 loading dots bubble (包含三点弹跳的等待气泡) 彻底移除，转而内嵌于同一个生成的回复气泡内，在 API 尚未输出任何文本前呈现 bouncing 弹跳动画。
- **无缝流式打字**：当 SSE 流式通道第一个文本包到达时，弹跳动画瞬间隐藏，并顺滑过度到 typewriter 动态文字打字效果，防止屏幕上出现一空一满两个气泡的冗余交互感。
- **微毫秒自适应滚动**：结合流式更新和短延迟，确保不管是移动端极简视口还是桌面大视口，文本内容都在视线最前方滚动对齐，免去游客拖曳。
- **精制交互控件**：重新为移动及桌面设计了金黄/琥珀色渐变的拍照按钮与翠绿/青色渐变的语音输入按钮，并具备录音态水波纹脉冲视觉回馈。

### 6. B端配置页三列弹性布局

对 `AdminAvatarScreen` (数字人形象管理) 进行了界面重构，解决了低分辨率大屏组件被挤压或隐藏的弊端：

- **排版架构**：抛弃了僵硬的 CSS Grid 占比定位，迁移到 Flex 弹性轴线排版 (`flex flex-col lg:flex-row gap-6 items-start`)。
- **硬编码宽度保护**：在组件内使用全局 HTML `<style>` 强制限定特定屏幕尺寸下的高权重定位：
  - **形象列表列**：锁定在 `280px` 宽，彻底杜绝列表内文字过长折行或多行挤缩，并在右侧配置垃圾桶删除按钮。
  - **媒体与预览列**：锁定在 `360px` 宽，用于居中显示数字人视频/图像帧预览和欢迎语调节。
  - **属性设置中列**：自适应拉伸 (`flex: 1 1 0%`) 占据全屏剩余空间，使得配置滑块与表单获得充足展现空间。

### AI 能力矩阵

| 业务场景 | 使用模型 | 调用方式 | Prompt 策略 | Fallback |
|---------|---------|---------|------------|---------|
| **数字人问答** | deepseek-v4-pro | SSE 流式 | RAG 上下文注入 + 情感标记强制 + 字数限制 | → deepseek.v3.1 |
| **行程路线生成** | deepseek-v4-pro | JSON Mode | 强制 JSON Schema + 景点 ID 约束 + 禁止 Markdown | → 本地硬编码路线 |
| **拍照识景** | Vision LLM (多模态) | Base64 图片 | 引导输出 subject/story/tip 三字段 JSON | → 默认景点文案 |
| **个性化欢迎语** | deepseek-v4-pro | 单次请求 | 注入时段/姓名/上次游览/偏好 + 30字内限制 | → 硬编码问候语 |
| **运营分析建议** | deepseek-v4-pro | 单次请求 | 分析最近 40 条对话，输出 Markdown 改进报告 | → 内置静态建议 |
| **语音转文字** | Web Speech API / Whisper | 音频流 | 景区专有名词纠偏（防"翠玉糊"误识） | → 打字输入 |
| **文字转语音** | Edge-TTS | 流式音频 | 选择景区 FM 女声，语速参数化 | → 浏览器 SpeechSynthesis |
| **MCP 工具调用** | deepseek-v4-pro | JSON-RPC | Tool Calling 标准协议 | → 直接 DB 查询 |

### Prompt 黄金策略

| 策略 | 说明 | 示例 |
|------|------|------|
| **情感标记强制** | 首行必须输出情感前缀 | `[情感: 愉快]您好！` |
| **RAG 知识约束** | 知识库外内容礼貌拒答 | 「小玉暂时找不到，建议前往服务中心」 |
| **JSON Mode** | 行程规划严格约束输出格式 | `response_format: {type: "json_object"}` |

### DeepSeek-V4-Pro 接入架构

```
deepseekChat() 调用流程：

try:
  POST https://eazo.ai/api/innoreation/v1/proxy
  Headers: X-Proxy-Key + Authorization Bearer
  Body: {model, messages, temperature, stream, max_tokens}
  
  if stream=true → SSE ReadableStream → AsyncIterator → 逐 chunk 推送前端
  if stream=false → await response.json() → 直接返回
  
catch (404/500):
  warn: "[DeepSeek 容灾] 自动回退至 deepseek.v3.1"
  return ai.chat({model: "deepseek.v3.1", ...})  // Eazo SDK
```
